# 文件说明

## 目录结构

```
src/so101_moveit_mujoco/
├── launch/so101_mujoco.launch.py           # MuJoCo 仿真主入口
├── launch/so101_display.launch.py          # mock 硬件显示（无仿真器）
├── launch/so101_moveit_servo.launch.py     # MoveIt Servo 实时微动（需配合 mujoco launch，手柄遥操见 xbox_control 工作区）
├── moveit_config/                          # MoveIt/Servo 配置（srdf、运动学、限位、servo 参数；与 gazebo 版差异见 doc/moveit_servo_接入记录.md）
├── urdf/so101.urdf.xacro                   # 机器人本体 xacro（mesh 用 package://）
├── urdf/so101_mujoco.ros2_control.xacro   # ros2_control 块（MuJoCo 插件/参数/joint 接口）
├── mjcf/so101.xml                          # 机器人 MJCF（GitHub 官方仓库下载，未修改）
├── mjcf/so101_scene.xml                    # scene（地板/灯光/include/meshdir覆盖）← mujoco_model 加载它
├── meshes/                                 # STL 网格（MuJoCo 加载 + RViz 渲染共用一份）
├── config/so101_ros2_control.yaml          # 控制器配置
├── config/so101_display.rviz               # RViz 配置
├── scripts/record_so101.sh                 # 数据采集脚本（ros2 bag record）
└── doc/                                    # 本文档 + moveit_servo_接入记录.md + mujoco_qa.md
```

## 各文件作用

### launch/so101_mujoco.launch.py

MuJoCo 仿真主入口。流程：xacro（传 `headless`）→ `robot_description` → robot_state_publisher → 启动 `mujoco_ros2_control` 的 `ros2_control_node`（内部同时跑 MuJoCo 物理线程和 controller_manager，Humble 下必须 remap `~/robot_description` → `/robot_description`）→ 3 秒后用 spawner 链式加载三个控制器（TimerAction + OnProcessExit 串联）。参数：`headless`（无 GUI 环境必选）、`rviz`、`model`。

### launch/so101_display.launch.py

mock 硬件显示（等价 gazebo 包的 `so101_display.launch.py`）。用 controller_manager 的 `ros2_control_node` + `mock_components/GenericSystem`，不起 MuJoCo，启动快，适合验证控制器配置和 RViz。

### urdf/so101.urdf.xacro

机器人本体描述（由 onshape-to-robot 生成的 `so101_new_calib.urdf` 变换而来）：mesh 路径为 `package://so101_moveit_mujoco/meshes/...`（与 MJCF 共用 `meshes/` 里同一份网格，不重复存放），删除 ROS1 风格 `<transmission>`，头部声明 `headless`/`use_mujoco` 两个 xacro 参数，末尾 include ros2_control 宏。原始纯 URDF 已删除（内容全部并入本文件）。

### urdf/so101_mujoco.ros2_control.xacro

ros2_control 配置，宏 `so101_ros2_control(use_mujoco, headless)`：
- MuJoCo 分支：插件 `mujoco_ros2_control/MujocoSystemInterface`，参数 `mujoco_model`（指向 `mjcf/so101_scene.xml`，**MJCF 路径的"源"就在这里**）、`sim_speed_factor`、`headless`
- mock 分支：`mock_components/GenericSystem`
- 6 个 joint（shoulder_pan / shoulder_lift / elbow_flex / wrist_flex / wrist_roll / gripper），指令接口 position，状态接口 position + velocity

### mjcf/so101.xml

机器人 MJCF，**原样下载自 GitHub 官方仓库 [TheRobotStudio/SO-ARM100](https://github.com/TheRobotStudio/SO-ARM100)**（`Simulation/SO101/so101_new_calib.xml`，LeKiwi 团队用 onshape-to-robot 从 Onshape CAD 导出），未做任何修改。与本包 URDF 是同一标定变体（链接名、惯性、关节限位一致），并带官方调好的 STS3215 舵机参数（kp=998.22, kv=2.731, forcerange ±3.35）和关节 damping/frictionloss——仿真行为与真机一致靠的就是这组参数。

四段结构：`<compiler>`（弧度单位、meshdir、autolimits）、`<default>`（sts3215/visual/collision 参数类）、`<worldbody>`（8 个 body 的树，每个带 fullinertia 惯性矩阵）、`<actuator>`（6 个 `<position>` 执行器，name = joint 名）。

### mjcf/so101_scene.xml

仿真场景入口，`mujoco_model` 参数实际加载的文件。内容：`<include so101.xml>` + 天空盒/棋盘格地板 + 平行光 + `<compiler meshdir="../meshes"/>`（覆盖官方 `so101.xml` 里的 `meshdir="assets"`，让 MJCF 也从包根 `meshes/` 取网格；MJCF 多 compiler 元素属性合并、后出现者优先，因此必须写在 include 之后）。要加相机、桌子、物体改这里，不要动 `so101.xml`。

### config/so101_ros2_control.yaml

控制器配置，与 gazebo 版一致：`controller_manager` update_rate 100；`so101_joint_state_broadcaster`（JointStateBroadcaster）；`so101_arm_controller`（JointTrajectoryController，5 个 arm 关节，position 指令 / position+velocity 状态）；`so101_gripper_controller`（JointGroupPositionController，gripper 关节）。

### scripts/record_so101.sh

数据采集脚本（对照 gazebo 版）：`ros2 bag record` 的封装，默认录 `/joint_states`、TF、`/robot_description`、`/clock`、手臂轨迹和夹爪指令话题（暂无相机话题，接入后加进 `DEFAULT_TOPICS`）。支持 mcap/sqlite3（缺插件自动回退）、按时长切分、自定义输出目录；录制前会逐个检查话题已上线。用法见 README"数据采集"一节或 `record_so101.sh -h`。

## 架构（与 gazebo 版对照）

| 环节 | gazebo 版 | 本包 |
|---|---|---|
| 物理引擎 | Gazebo Classic + `gazebo_ros2_control` 插件 | MuJoCo + `mujoco_ros2_control` 的 `ros2_control_node` |
| 仿真模型 | URDF 直接 spawn | **MJCF**（`mjcf/so101_scene.xml`，MuJoCo 只读 MJCF 不读 URDF） |
| URDF 角色 | 仿真模型 | 只给 controller_manager 提供 `<ros2_control>` 标签 |
| 硬件插件 | `gazebo_ros2_control/GazeboSystem` | `mujoco_ros2_control/MujocoSystemInterface` |
| controller_manager | 插件内部运行 | `mujoco_ros2_control/ros2_control_node` 内部运行 |
| 控制器 | JSB + JTC + JointGroupPosition（同名同配置） | 相同 |

两边通过 **joint 名** 对齐：URDF `<ros2_control>` 里的 joint 名必须等于 MJCF 里 `<position>` actuator 的 name（6 个：shoulder_pan / shoulder_lift / elbow_flex / wrist_flex / wrist_roll / gripper）。

数据流：

```
urdf/so101.urdf.xacro ──┬─> robot_state_publisher ─> /tf + RViz（用 urdf/assets 渲染）
                        └─> ros2_control_node (controller_manager)
                             解析 <ros2_control> 标签（插件/参数/joint）
                                   │ 按 joint 名对齐
mjcf/so101_scene.xml ────> MujocoSystemInterface ─> MuJoCo 物理仿真
```

## 已知告警（无害）

- KDL `root link has an inertia`：base_link 带惯性所致，gazebo 版同样存在；要消除可加 dummy world link（MuJoCo 侧不需要）
- JTC `allow_nonzero_velocity_at_trajectory_end` deprecated：Humble 控制器默认值提示
- `Could not enable FIFO RT scheduling`：无实时调度权限，学习用途可忽略
